## 上行和下行，各要多少兆才够用？

主播端真正吃紧的是上行带宽。直播时手机或相机要把画面实时推给平台，这条路走的是上传；下行主要负责加载评论、商品链接这些零碎请求，压力小得多。

按画质对应的上行带宽参考值如下：

| 直播画质 | 建议上行带宽 |
| --- | --- |
| 标清（SD） | 1–2 Mbps |
| 高清（720p/1080p） | 3–5 Mbps |
| 4K | 10 Mbps 起 |

有三个变量会往上加码：帧率开到60fps、码率拉高、音频用高码率流，都会多占带宽。反过来，用H.264或H.265这类高效编码压一压，同样的画质能省下不少流量。这也是为什么同样是“高清直播”，有人3M撑得住，有人5M还嫌紧。

比较稳妥的做法是留余量：专线环境下，上行配到5–10 Mbps、下行10–20 Mbps，多出来的部分用来应对码率波动、弹幕互动和突发重传。按这个标准，手机直播配15M线路、相机直播配30M线路，正好落在安全区间。

## 比速度更致命的三个指标：延迟、抖动、丢包

速度达标只解决了“够不够”，直播卡不卡，还要看三个指标。

延迟决定互动体验。观众发一条评论，主播几秒后才反应，带货节奏就全乱了。经过优化的专线能把延迟压到150ms以内；而公共VPN绕行国际线路，延迟普遍在200ms开外。
